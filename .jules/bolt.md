## 2024-10-29 - React O(N^2) Render Loop Bottleneck via Storage Fetches
**Learning:** Found a critical performance anti-pattern where a component mapped over a large array and executed an `Array.prototype.find()` on another synchronously fetched array on every render. Because local storage fetches (`getHistory`, `getUpdates`) were unmemoized inside the component body, any trivial state update (like typing in a search bar) caused a severe O(N*M) calculation blocking the main thread.
**Action:** Always memoize derived heavy calculations and convert arrays used for lookup into `Map` structures using `useMemo` when rendering lists. Use global props (like `bookmarks`) as proxy dependencies to trigger updates for local storage fetches to maintain freshness without unnecessary re-renders.
